# ADR 0013. Фото: OpenRouter vision, base64, отдельный VisionClient

**Статус:** принято

## Контекст

Нужно принимать фото в Telegram и включать снимок в занятие преподавателя. OpenRouter принимает изображения только через `/api/v1/chat/completions`: в `content` — части `text` и `image_url`. Поле `image_url.url` бывает двух видов: публичная HTTP(S)-ссылка или data URL `data:image/<тип>;base64,...`. Telegram отдаёт не публичную картинку, а `file_id`; скачать файл можно только с токеном бота, ссылка живёт около часа.

Текстовый преподаватель может работать через Ollama. URL фото — тот же `Config.base_url`, что у текста ([ADR 0003](0003-openai-client-two-providers.md)). История диалога — текстовые словари `{role, content}` без байтов ([ADR 0008](0008-in-memory-message-dicts.md)).

## Подходы

**Как передать пиксели в OpenRouter**

| Подход | Суть | Почему нет / да |
|---|---|---|
| Публичный URL | Провайдер сам качает картинку по HTTP | У файла из Telegram нет публичного URL |
| URL Telegram `getFile` | Подставить `https://api.telegram.org/file/bot<token>/...` в `image_url` | Токен утекает третьей стороне; ссылка временная; провайдер часто не может её скачать |
| Выложить в S3/CDN | Скачать у Telegram, залить в хранилище, отдать публичный URL | Лишняя инфраструктура, вне видения |
| Base64 data URL | Скачать байты у Telegram, закодировать, вложить в запрос | Картинка приватная; байты уходят только в API-вызов |

**Как встроить разбор в диалог**

| Подход | Суть | Почему нет / да |
|---|---|---|
| Один вызов: фото сразу в `LlmClient` | Преподаватель-модель сама смотрит картинку | Текстовый провайдер может быть Ollama без vision; в историю пришлось бы класть мультимодальный `content`; `LlmClient` перестал бы быть текстовым |
| Картинки в истории | Хранить base64 или `file_id` и слать vision-модели весь диалог | Раздувает память и токены; `file_id` бесполезен для OpenRouter; противоречит [ADR 0008](0008-in-memory-message-dicts.md) |
| Два шага: vision → текст → преподаватель | Отдельный клиент описывает снимок; в историю и к преподавателю идёт только текст | Совпадает с видением: байты в историю не пишем; URL тот же, что у текста |

Отдельный OCR (Tesseract и т.п.) не рассматриваем: vision-модель и так читает конспект, схему и скрин, лишняя зависимость не нужна.

## Решение

`TelegramBot` скачивает файл фото (наибольший размер из `message.photo`) и передаёт байты и подпись в `Assistant`. К API провайдера хендлер не ходит.

`VisionClient` вызывает chat completions тем же пакетом `openai`, что и текст, но своим `AsyncOpenAI` с `base_url` из `Config` (`LLM_BASE_URL` или таблица по `LLM_PROVIDER`) и ключом `LLM_API_KEY`. Модель — `VISION_MODEL`, промпт — `VISION_PROMPT`. В сообщении сначала текст (промпт + подпись, если есть), затем `image_url` с data URL. MIME для сжатых фото Telegram — `image/jpeg`. На выходе — строка: что на фото и что с ним делать в занятии.

`Assistant` кладёт этот текст в историю как реплику пользователя и вызывает `LlmClient` как для обычного сообщения. Байты и base64 в историю и в лог не пишутся.

Стикеры и прочий нетекст по-прежнему без ответа.

## Следствия

Смена vision-модели или промпта — правка `.env`, код не меняется. URL не зашит в код: фото идёт туда же, куда текст. Запрос крупнее, чем у публичного URL; для учебных снимков из Telegram это приемлемо. Реализация — итерация 11 в `docs/tasklist.md`.
