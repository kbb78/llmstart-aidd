# Техническое видение

Документ — исходная точка разработки. Цель первой версии: проверить идею текстового LLM-ассистента в Telegram с ролью из системного промпта.

Вне первой версии: база данных, webhook, очереди, RAG, облако, фреймворки агентов.

Связанные решения: [ADR](adr/).

## Технологии

| Слой | Выбор |
|---|---|
| Язык | Python 3.12+ |
| Зависимости | `uv`, манифест `pyproject.toml` |
| Сборка и команды | `make` (обёртка над Docker Compose); в образе зависимости ставит `uv` |
| Запуск | Docker Compose локально |
| Telegram | aiogram 3, long polling |
| LLM | официальный клиент `openai` |
| Провайдеры LLM | OpenRouter и локальная Ollama (оба — OpenAI-совместимый API) |
| Конфиг | переменные окружения, файл `.env` |
| Логи | стандартный модуль `logging` |
| История диалога | память процесса, без БД |

Переключение провайдера — переменная `LLM_PROVIDER` в `.env` (`openrouter` или `ollama`). URL по умолчанию выбирает `Config`. Ключ и имя модели — отдельные переменные. Код вызова LLM один: клиент `openai`.

Команды `make` — тонкие обёртки над `docker compose`. Зависимости в образе ставит `uv` по `pyproject.toml` и `uv.lock`.

## Принцип разработки

1. **KISS.** Новый класс, файл или зависимость — только если без них бот не работает или код становится запутаннее.
2. **OOP.** Поведение — в классах. Модули с набором свободных функций не плодим.
3. **Один класс — один файл.** Имя файла = имя класса в snake_case (`llm_client.py` → `LlmClient`).
4. **Корень кода:** `src/assistant/`. Плоская структура пакета, без слоёв `core` / `infrastructure` / `domain`.
5. **Тонкий слой Telegram.** Хендлер принимает сообщение и отдаёт текст ответа. Диалог и вызов LLM — не в хендлере.
6. **Без абстракций «на вырост».** Провайдер LLM — конфиг одного клиента `openai`. Нет DI-контейнера и фабрик ради фабрик.
7. **async** только там, где его требуют aiogram и клиент OpenAI.
8. **Секреты и параметры запуска** — только в `.env` (и переменных окружения). В код не вшиваем ключи, URL, имена моделей, токен бота.

## Структура проекта

```
Makefile
pyproject.toml
.env.example
docs/
src/assistant/
  __init__.py
  __main__.py
  config.py
  llm_client.py
  chat_history.py
  assistant.py
  telegram_bot.py
```

| Файл | Класс | Роль |
|---|---|---|
| `config.py` | `Config` | читает окружение |
| `llm_client.py` | `LlmClient` | вызов chat completions |
| `chat_history.py` | `ChatHistory` | история в памяти по `chat_id` |
| `assistant.py` | `Assistant` | системный промпт + история + LLM → ответ |
| `telegram_bot.py` | `TelegramBot` | polling и хендлеры, вызывает `Assistant` |

Исключения из «один класс — один файл»: `__init__.py`, `__main__.py`. Точка входа собирает объекты и запускает бота. Хендлеры живут в `TelegramBot`, отдельный класс хендлеров не заводим.

`.env` в репозиторий не коммитим. В git — `.env.example`.

## Архитектура

Один процесс. Объекты собираются вручную в `__main__.py`, контейнера DI нет.

Поток сообщения:

```
Telegram
    → TelegramBot (текст + chat_id)
        → Assistant
            → ChatHistory (дописать user, взять контекст)
            → LlmClient (системный промпт + история)
            → ChatHistory (дописать assistant)
        ← текст ответа
    ← send_message
```

- `TelegramBot` использует `Assistant`.
- `Assistant` использует `ChatHistory` и `LlmClient`.
- `Config` отдаёт токен бота, провайдера LLM (`LLM_PROVIDER`), URL, ключ, модель, системный промпт. Смена провайдера — правка `.env` и перезапуск, без изменения кода.

Системный промпт — переменная `SYSTEM_PROMPT` в `.env`. Ответ в Telegram — целиком, без стриминга. Ошибка LLM или сети: запись в лог и короткое сообщение пользователю. Ретраев и очередей нет.

## Модель данных

БД и ORM нет. Состояние только в памяти процесса.

**История** — словарь: ключ `chat_id` (int из Telegram), значение — список реплик.

**Реплика** — словарь в формате OpenAI: `role` (`user` | `assistant`) и `content` (str). Класс `Message` не заводим.

Системный промпт в истории не хранится. `Assistant` каждый раз ставит его первым сообщением при вызове LLM.

**Лимит:** `MAX_HISTORY_MESSAGES` в `.env`, по умолчанию 20 реплик на чат. При превышении `ChatHistory` удаляет самые старые реплики.

Других сущностей (пользователь, сессия, учёт токенов) нет.

## Работа с LLM

`LlmClient` держит один `openai.AsyncOpenAI`. Метод один: список сообщений → текст ответа. Стриминга нет.

`Config` выбирает `base_url`:

| `LLM_PROVIDER` | `base_url` по умолчанию |
|---|---|
| `openrouter` | `https://openrouter.ai/api/v1` |
| `ollama` | `http://localhost:11434/v1` |

Если задан `LLM_BASE_URL` — используется он, таблица не применяется. Ещё из `.env`: `LLM_API_KEY`, `LLM_MODEL`. Для Ollama пустой ключ заменяется на заглушку `ollama`. Неизвестное `LLM_PROVIDER` — ошибка при старте, бот не запускается.

`Assistant` собирает запрос: первым идёт `system` из `SYSTEM_PROMPT`, затем история чата. Параметры сэмплинга не выносим в конфиг.

Других клиентов, retry-библиотек и обёрток нет.

## Сценарии работы

**Запуск.** Процесс читает `.env`, проверяет обязательные переменные, стартует long polling. Невалидный `LLM_PROVIDER` или пустой токен Telegram — выход с ошибкой в логе.

**`/start`.** Короткое приветствие. История чата не меняется.

**Текст.** Сообщение пользователя → `Assistant` → один ответ модели.

**Нетекст** (стикер, фото, голос и т.п.) — без ответа и без вызова LLM.

**Ошибка LLM или сети.** Пользователю фиксированная фраза: не удалось получить ответ, попробуйте ещё раз. В лог — исключение. Реплика пользователя в историю не пишется, если модель не ответила.

Команды сброса истории нет. Рестарт процесса очищает память. Смена роли — правка `SYSTEM_PROMPT` и перезапуск.

## Конфигурирование

`Config` при создании вызывает `load_dotenv()` и читает окружение. Нет обязательного значения — исключение, процесс не стартует. Файлов YAML/TOML для приложения нет.

| Переменная | Обязательна | Смысл |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен бота |
| `LLM_PROVIDER` | да | `openrouter` или `ollama` |
| `LLM_MODEL` | да | имя модели у провайдера |
| `SYSTEM_PROMPT` | да | роль ассистента |
| `LLM_API_KEY` | для OpenRouter — да; для Ollama — нет | ключ API |
| `LLM_BASE_URL` | нет | перекрывает URL провайдера |
| `MAX_HISTORY_MESSAGES` | нет | по умолчанию `20` |
| `LOG_LEVEL` | нет | по умолчанию `INFO` |

В git: `.env.example`. Файл `.env` в `.gitignore`. Смена провайдера: `LLM_PROVIDER` (плюс ключ и модель), перезапуск.

## Логирование

Стандартный модуль `logging`. Один обработчик — stdout. Формат: время, уровень, логгер, сообщение. Файлов, ротации, JSON, внешних сервисов нет.

Уровень — `LOG_LEVEL`, по умолчанию `INFO`. Настройка один раз при старте в `__main__.py`.

В лог:

- старт: провайдер и модель (без ключей и токена)
- входящее текстовое сообщение: `chat_id` и текст
- ответ модели: `chat_id` и текст
- ошибка LLM/сети: исключение (`exc_info`)
- невалидный конфиг: ошибка и выход

Секреты из `.env` в лог не пишем.

## Сборка и деплой

Первая версия запускается на своей машине. Docker, CI, облако, systemd в проект не входят.

В корне: `pyproject.toml` (пакет, зависимости, Python ≥ 3.12), `uv.lock` в git, `Makefile` как обёртка.

| Цель | Действие |
|---|---|
| `make install` | `uv sync` |
| `make run` | `uv run python -m assistant` |

Деплой: clone, `make install`, заполнить `.env`, запуск. Публичный URL не нужен: long polling сам ходит к Telegram.

**Передний план:** `make run`, остановка Ctrl+C.

**Фон.** Отдельных скриптов и целей Make нет — `nohup` или `screen` уже есть в ОС (Linux / macOS / WSL). Логи бота идут в stdout, их нужно перенаправить в файл (`.gitignore` уже игнорирует `*.log`).

`nohup` — процесс переживает закрытие терминала:

```bash
nohup make run > bot.log 2>&1 &
```

Остановка: найти pid (`pgrep -f "python -m assistant"`) и `kill <pid>`.

`screen` — удобно смотреть лог живьём:

```bash
screen -S assistant
make run
```

Отключиться: Ctrl+A, D. Вернуться: `screen -r assistant`. Остановить бота: вернуться в сессию и Ctrl+C.
